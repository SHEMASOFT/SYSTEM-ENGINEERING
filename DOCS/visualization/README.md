# Workflow visualization

Interactive map of how SYSTEM ENGINEERING runs a workflow: intake, orchestrator,
route selection, model runtime, output transport, gates, checkpoint, plus the
advisory memory link and the read-only `se trace` command.

It is a **static page with no dependencies**: one self-contained `index.html`
(HTML + CSS + JS inline, no external URL), the two generated diagrams
(`diagram.svg`, `diagram.mmd`) and the generator that produces them from the
model.

## Open it

- **Locally:** double-click `index.html`; it works over `file://`, no server.
- **Published:** <https://shemasoft.github.io/SYSTEM-ENGINEERING/> — served by
  GitHub Pages once *Settings → Pages → Source* is set to **GitHub Actions**
  (the workflow in `.github/workflows/pages.yml` deploys this folder).

## What it is, and what it is not

- It is **documentation**: it reads the repository's contracts and explains the
  workflow shape, the two execution routes and the honest limits of each
  capability.
- It is **not a runner**: the page never calls a model, never runs a command and
  never writes to the repository.
- Colour is never the only signal: every node carries its textual status label.

## Snapshot policy

The capability audit behind the page — evidence `archivo:línea`, statuses and
known limitations — was taken against **`p3-complete @ 4c18480` (2026-10-30)**.
The contract numbers in the header (**0.12.0**, 27 commands, 12 agents,
7 skills) are the current ones.

When the code moves, the evidence line numbers must be re-audited. Until then
the page states which snapshot it describes instead of pretending to be live.

## Regenerate the static diagrams

```bash
node tools/generate.mjs
```

The generator is deterministic: two consecutive runs produce byte-identical
files, so an empty diff proves nothing was regenerated by accident. The single
source of truth is `SE_MODEL`, inside the `<script>` of `index.html`: never edit
`diagram.svg` or `diagram.mmd` by hand.
